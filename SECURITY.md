# Security policy

CrisisWeave may be deployed around sensitive crisis and recovery data. Do not open a public issue containing credentials, private survivor information, precise private locations or working exploit details.

Use GitHub private vulnerability reporting / Security Advisories for this repository when available. If that private channel is unavailable, contact the maintainer through a private contact method published on the maintainer's GitHub profile and keep sensitive details out of public channels.

Reports should identify the affected revision, impact and reproducible steps using synthetic data where possible. Security fixes target current `main` and revisions promoted by the `davidmariscalf/CrisisWeave` component lock.

For a suspected live compromise, operators should stop unsafe exposure, revoke credentials, preserve audit evidence and follow their deployment incident-response runbook. CrisisWeave is not an emergency authority.
